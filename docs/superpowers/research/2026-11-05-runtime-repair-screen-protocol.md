# Runtime repair: six-task screen

This exploratory screen follows the completed
[LC.35 comparison](../../../evals/2026-11-05-actionable-acceptance/README.md).
It measures the combined timeout-wrapper/refusal, task-scope and explicit
observed-startup-failure corrections. Their individual effects are not separated.

Collect six fresh gated Easy Phase1 tasks, sequentially, with the same five
selective remedies plus check/external-acceptance. No S outcomes are collected
or reused as a contemporaneous control. Original acceptance/hidden/health/layout/
settlement usability intersection remains; typing and semantic reservations
are reported separately. Every model failure counts; retain all attempts and
costs, with no mid-cohort edits, favorable retries or replacement. Instrument
integrity failure stops collection and is retained as an explicit incomplete
screen. A corrected instrument needs a separately frozen fresh cohort.

Same M5 Max, Pi1.4.0, llama.cpp11669/620d2225c, pinned Q4_K_M weights, thinking,
1/.95/20 sampling,16384 output and existing context/KV config. One task at once;
two repairs,600s shared deadline,180s tool cutoff,30s checks,8h independent
watchdog and full660s reserve per new task. Freeze this protocol, image, package,
source, backend and profile. Qualify boundary, valid builds/omissions/hostile data,
native repairs/tamper/exhaustion, compaction and real warning delivery first.

Report all six registered components/outcomes, requests, ordinary turns,
complete output or unknown, elapsed, repair costs and semantic/typing limits.
A zero usable-result denominator stays undefined. Native compaction/retries
stay in relay totals; partial known output is never a whole total.

The decision is always screen_only: no preset/default promotion or reliability
rate claim. A clean6/6 is only a lead for a new preregistered deciding comparison.
Any remaining failure requires diagnosis before another change; do not code
an application answer into a generic remedy or tune the oracle to a result.
Continued scope expansion, blocked-output confusion, an actual startup failure
ignored after observed feedback, or a valid build rejected falsifies the fixes.
No effect claim is made from the six alone.

Stop owned inference at finish/failure, verify server/controller/guardian, port,
owned containers/volumes and input hashes independently. Raw evidence stays
local; no public push or upload without explicit publication authorization.
