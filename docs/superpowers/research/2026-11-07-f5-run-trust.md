## The budget limits

The 24 lc40 Easy sessions used about 17 requests and 7,000 output tokens at the median, 63 and
28,955 at most. lc40's 120 / 64,000 is about twice anything Easy used, so Easy gets **64 / 32,000**
(none of the 24 would have been cut); Medium and Hard keep **120 / 64,000** until R.2 and R.3
measure them. Per request: 16,384, also charged when a successful stream breaks with no usage;
a failed response (a 400, an unreachable server) is counted but charged nothing, so a host fault
never reads as spent budget (final review, 2026-11-07).
`wall_safety` 1,200 s, three times the slowest Easy session; lc40's 3,600 s guarded little.

## Where we differ from `33e0b92`

Andre counts requests from `MELLUM_DELEGATE_PROFILE`, one line per request tagged by role, and
enforces nothing beyond `MELLUM_TURN_CAP`. Its idea is right: requests are reproducible and
countable on a killed run. We do not build the budget on it because it lives in the worker
extension, which Vanilla (R.1's control) does not load; it sees the outgoing prompt, not the
output tokens or a broken stream; and it observes rather than stops. The proxy sits at a boundary
every arm shares. His profiler stays as the role-split diagnostic A.1 will want.

## Ladder run

The numbers above are `llama-perplexity` runs, not sessions. F.5's own run, on b12110 with Pi
1.4.0 and the follower on screen ([record](../../../evals/2026-11-07-f5-smoke/table.md)):

- **Host card passed** in 180 s: identity with every pinned flag, 42,658 prompt tokens per slot,
  protocol, stability 10/10, numerics 0.57%, tooling as pinned.
- **Three counted Vanilla Easy sessions** (n = 1 each): two `settled`, one `stalled` on a
  foreground `uvicorn --reload` (180 s). 18–23 requests and 6,369–7,860 output tokens, so Easy's
  64 / 32,000 bound none. The proxy's counts equal the recorder's in all three.
- **One uncounted session with a 5-request budget** ended `budget` after 11 s: the proxy refused
  the sixth request and logged `budget_exhausted` once; `counted: false`.
- No session passed all 13 checks. All three counted ones miss the title override (pathology 20).
  That is a model habit for R.1, not a reading on F.5.

**Correction, 2026-11-07 (Paul).** The plan had the harness refuse any run without a card, with
`--uncounted` to opt out. That would have broken Andre's `/challenge` and the lesson commands,
and left an uncounted run with no bound. A run is now counted exactly when it has `--host-card`.
Every tier run is held to its `budget.json` either way, and a run without a card says
`counted: false`.

## Persuasion → enforcement

A host used to count because it ran. From F.5 a counted session needs a host card that passed,
for the server that is live, and a budget that a proxy refuses past rather than one we read later.

## What would falsify this

- The host card's capacity, protocol or stability items fail on b12110 although numerics pass.
- An Easy Vanilla session on b12110 hits 64 requests while still converging, more often than the
  lc40 sessions suggest; then the limit measures the cap, not the cost.

## Risks

- Brew can move the build again; the pin card's identity item will then fail, which is intended.
- Four chunks is a short text; 0.57% is one measurement of each backend.
