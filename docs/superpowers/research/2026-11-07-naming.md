# Naming: the arms, the worker's states and the tiers, made unambiguous

## For Andre

- **What this is:** a pass over the names we use for tiers, arms and the worker, after Paul found
  he could not tell `bare` from Vanilla. The glossary (`learn/glossary.md`) is the single source;
  this note says what changed there and why, so your notes and ours use the same words.
- **One behaviour fix rode along.** `/challenge <tier>:vanilla` ran the `bare` arm, not
  `vanilla`. It now runs `vanilla`, the floor. Nothing else changed behaviour.
- **What to look at:** the table below, and the three questions at the end. If a name here
  differs from what you use, say so and we will settle it before R.1 writes its preregistration.

**What is measured.** Nothing; no run. The names are read from the code on `integration`
(`learn/code/harness.py` `ARMS`, `extensions/mellum-worker.ts`, `extensions/mellum-remedies.ts`,
`remedies/presets/`).

**What is conjecture.** That `bare` and `vanilla` send the same requests on a one-task headless
session. The harness comment and the baseline tests say so; no record compares the two payloads
on the repaired oracle.

## Ladder run

None. Names and one command's arm changed; no measured setting did.

## Persuasion → enforcement

A name in prose is persuasion. The two places where a wrong name changed what ran are now
pinned by tests: `challengeTarget` (`tests/challenge-score.test.mjs`) maps `:vanilla` to the
`vanilla` arm, and the `/mellum` description may not promise a prompt or tools
(`tests/mellum-worker-hooks.test.mjs`).

## The names

| Name | What it is | Arm or flag |
| --- | --- | --- |
| **Tier** | One of the three suites: Easy, Medium, Hard (13, 18, 34 current checks) | `--suite easy` |
| **Vanilla Pi**, the floor | Pi plus the recorder; no worker extension, no remedies | `--arm vanilla`, `/challenge easy:vanilla` |
| **`bare`** | The worker extension loaded, mode off. Sends Vanilla's requests, but is not Vanilla | `--arm bare` |
| **Mellum mode** | What `/mellum on` switches on: the model becomes Mellum, turns before the on-marker are dropped from each request, the span is counted, and `off` writes the run record | `MELLUM_MODE=1` |
| **Thin worker** | The worker with mode on and nothing else; bundles no prompt, tools or guards | `--arm worker`, `/challenge easy` |
| **Baseline Worker** | The worker before LC.29 (2026-10-31): mode plus a bundled prompt, tool narrowing, facts and guards. Today: the thin worker plus `preset:baseline-worker` | `--arm worker --remedy preset:baseline-worker` |
| **Base** | The smallest stack that gives later remedies a fair chance, earned against plain Vanilla in R.1 | `--remedy preset:base` |
| **Tier preset** | The remedy stack measured for a tier | `--remedy preset:easy` |

## What changed

- **"bare Pi" is no longer an alias of Vanilla Pi.** The glossary auto-links aliases, so a page
  saying "bare Pi" linked to Vanilla while `bare` is another arm.
- **Mellum mode and the thin worker get entries.** The glossary used "Baseline Worker" for the
  thin worker, while `preset:baseline-worker` is the old bundle; the same words meant both.
  "Baseline Worker" now keeps its historical meaning, which the records and scoreboard rows from
  October use.
- **The `/challenge` pages say "thin worker"**, not "Baseline Worker (the shipped bundle)".
- **Base comes back, earned.** On `lc40-thin-worker`, Base (`base.json`: the 30 s bash bound
  plus `prompt/name-the-layout`) was assumed. R.1 now measures those units against plain
  Vanilla first, and only the winners become `preset:base`; remedies are then measured on Base,
  with Vanilla in the batch. The name stays apart from the Baseline Worker, the old bundle.
- **The tier presets are marked as placeholders.** `easy`, `medium` and `hard` hold the same four
  units, carried from before the oracle repair; R.1–R.3 rebuild them from measurement.
- **Easy's check count is 13** in the Challenge entry (it said 4, from before F.4).
- **The worker's header and `/mellum` description** no longer say it swaps in a prompt and tools.

## Left as is, on purpose

- **Historical docs** (`LEARNING.md`, `LESSONS.md`, `EXAMPLE.md`, `docs/recipe.md`, old research
  notes and plans) keep their words: "bare Pi" there means what we now call Vanilla Pi, and
  "Baseline Worker" means the bundle. Rewriting records is not ours to do.
- **The scoreboard** (`learn/code/scoreboard.py`) labels the `worker` arm "Baseline Worker".
  Its October rows were the bundle, so relabelling them would misreport them.
- **The harness default arm is `bare`.** A run with no `--arm` loads the worker extension. Every
  counted run names its arm, so this changes nothing measured, but it surprises.
- **"Tier 4" on `lc40-thin-worker`** meant a round of prompt-fragment screens, not a fourth
  suite. It is not carried over.

## Questions for you

1. Does the table match the names you use, especially "thin worker" for `--arm worker` and
   Base for the earned minimal stack?
2. Should the harness default to `--arm vanilla`, the floor, rather than `bare`?
3. Should the scoreboard label new `worker` rows "thin worker" from a cut-off date?

## What would falsify this

- A record on the repaired oracle in which `bare` and `vanilla` send different requests on the
  same task. Then `bare` is not "Vanilla's requests", and the table is wrong.

## Risks

- The `Tier` alias may link the first "tier" on pages where it means something looser.
- Learners who already ran `/challenge easy:vanilla` have records under `bare`; their picker
  labels still read "vanilla", which is what they meant.
