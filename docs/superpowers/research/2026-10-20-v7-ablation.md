# Ablating the v7 mediated lift: which change cracks rung 9?

Date: 2026-10-20. A **screen** (exploratory, n=3), isolating the lift behind
the 12/12 win recorded in
[`2026-10-20-mediated-6-9-v7.md`](2026-10-20-mediated-6-9-v7.md). That run
stacked four changes at once, so it is a method comparison, not an ablation —
this toggles each change back, one at a time, to see which one carries rung 9
(the phase-4 auto-`id` miss that capped every prior arm at ≤2/3).

## Preregistration

**Baseline = the win config** (reused from
[`evals/2026-10-20-mediated-6-9-v7/`](../../ladder/2026-10-20-mediated-6-9-v7/),
rung 9 = **3/3**): Mellum, direct/oMLX, mediated frozen `test_phase4.py`,
`--redispatch 5 --effort-ramp --thinking off`, v7 prompt, focused command
`pytest tests/<name>`, trimmed tools `read,ls,bash,edit,write`.

Each arm changes **exactly one** setting back to its pre-win value; the other
three stay at the win value:

| arm | toggled back to | mechanism |
|---|---|---|
| A — v6 prompt | v6 worker prompt | `--prompt mellum-worker-v6.md` |
| B — whole-dir cmd | `pytest tests` | source edit (no `--tools`/cmd flag) |
| C — grep/find tools | `read,grep,find,ls,bash,edit,write` | source edit to `TOOLS` |
| D — fixed high | no ramp, `--thinking high` | drop `--effort-ramp` |

- **Primary rung: 9** (phase 4), the discriminator. n=3 per arm.
- **Scoring:** `check.passed` per run — the AgentClinic hidden oracle
  (`check_agentclinic(4)`), the same scorer as the win; not the frozen
  acceptance test the worker sees.
- **Decision rule:** an arm whose rung-9 rate falls below the baseline 3/3
  implicates its change as load-bearing for the crack; an arm that holds 3/3
  says its change is not what cracked rung 9.
- **Secondary:** for any arm that moves rung 9, run rungs 6–8 (n=3) to check
  whether that change regresses the easier rungs.
- **Compute note:** primary set is 4 arms × rung 9 × n=3 = 12 runs; the full
  6–9 matrix is deferred to the movers, to bound cost.
- **Scope:** n=3 screen, one machine, one clean run per arm. Reproducibility
  improvement over the win: the frozen acceptance tests are copied into the
  record dir (the win left them in an ephemeral scratch dir).

## Results

Rung 9, n=3 per arm. Each arm toggles one setting back from the win; the other
three stay at the win value.

| rung 9 | win (baseline) | A v6-prompt | B whole-dir | C grep/find | D fixed-high, no ramp |
|---|---|---|---|---|---|
| **pass/n** | **3/3** | **3/3** | **3/3** | **3/3** | **3/3** |
| avg wall | 272s | 701s | 3075s | 348s | **163s** |
| re-dispatches | 2 | 2–3 | 2 | 2–3 | **0** |

No arm moved rung 9 below the baseline 3/3, so by the decision rule **no arm is
load-bearing** for the crack, and the secondary 6–8 runs are not triggered.

## Reading

**None of the four v7 changes carries the rung-9 crack.** Toggling each one back
— v6 prompt, whole-directory test command, grep/find tools — still gives 3/3.
They are **cost** knobs, not correctness knobs:

- **whole-dir command**: 3/3 but ~10× the wall time (3075s vs 272s) — the v6
  spin, the worker chasing unrelated tests. The focused command's win is
  **speed**, confirmed.
- **v6 prompt**: 3/3, somewhat slower/noisier (one 1681s straggler).
- **grep/find tools**: 3/3, modest overhead.

**The lever is a complete frozen test + enough thinking budget.** Arm D — fixed
`high` thinking, no fail-fast ramp — passes rung 9 **on the first attempt, zero
re-dispatches, and fastest of all (163s)**. The fail-fast ramp starts cheap
(`off`/2k) and has to *climb* to the budget rung 9 needed anyway, which is why
the ramped arms each burn 2–3 re-dispatches to reach the same 3/3.

So the 12/12 win is better read as: **the mediated frozen test + a sufficient
budget crack rung 9; the v7 prompt/command/tools and the ramp are efficiency
choices around that**, not the cause of the crack.

### Trade-off the ablation exposes
The fail-fast ramp is a *global* cost optimization across mixed difficulty —
it wins easy rungs cheaply by starting small. On a known-hard rung (9) it is
the wrong default: fixed-high is both more reliable-per-attempt and faster.
A difficulty-aware first budget (small for easy rungs, high for the known-hard
phase) would get the best of both. Candidate follow-up.
