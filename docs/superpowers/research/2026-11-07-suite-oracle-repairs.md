## Independent review

One whole-branch review found nine Important issues; all were accepted and repaired
in one test-first pass. `test_oracle_review.py` retains 18 cases: initial execution
showed 14 failures and one passing control, then two added execution-hook witnesses
failed separately. A late collection-hook mutation also failed before repair;
the trusted collector now inspects items after submitted collection hooks finish.

The fixes separate scoreboard identities; derive starter integrity from the trusted
prepared variant; inventory added tests and disable submitted execution/report hooks;
accept outer title blocks and bound date objects; reject readonly fields, negated
badges and hidden welcome text; and observe SQLite VM computation instead of a
function-name whitelist. Fixtures and generated parameters remain supported.
Private-row totals also pass an exact integer recursive-CTE implementation.

Historical assertion/dependency/starter inputs are retained for `bc5db20` and
`16cf9f9^`. The original-byte manifest covers all 25 prompt/spec files from the
latter revision. A valid post-init timestamp build passes recent assertions and
fails the older mechanism-specific assertion under the same new execution policy.

## Limits

The HTML checks observe server responses and static DOM semantics, not full CSS or
JavaScript rendering. The launcher exercises real uvicorn reload on an isolated
port and cleans up interrupted probes. Windows cleanup is implemented but was not
executed on this macOS host. SQL controls observe aggregation/arithmetic in SQLite's
compiled instructions plus varied real results; finite alternatives do not prove
every equivalent query is accepted. Configuration isolation is not an operating-
system sandbox for arbitrary hostile Python. No live model run, historical model
record rescore, or exhaustive input exploration was performed.
