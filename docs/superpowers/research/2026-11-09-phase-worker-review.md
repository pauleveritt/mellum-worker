## For Andre

**Date:** 2026-11-09. **Question:** how does Mellum implement Paul's Easy or Medium
roadmap, one requested phase at a time, with useful completion at bounded cost?
**What is measured:** the retained R.1/F.6 records, code inspection and saved-build
replays; this review starts no model session. The [evidence ledger](2026-11-09-phase-worker-review/evidence.md)
preserves calculations, corrections, source provenance and the imported reviews.
**What is conjecture:** savings from proposed remedies, transfer to later Easy
phases, Medium reliability, and economic benefit against direct stronger-model work.

### Firm decisions

1. **Keep the architecture:** Vanilla Pi plus recorder is the floor; the worker
   remains a command tool; each remedy is explicit, additive and agnostic.
2. **The Easy completion gain is real; Base remains unaccepted.** The count's
   preregistered cost clause failed. No retrospective metric accepts it; all
   tier presets stay empty until their own applicable deciding run succeeds.
3. **Keep our stronger work when reconciling with Andre:** thirteen-check Easy
   grading, supplied-test integrity, preregistered counts, enforced request/token
   budgets, compaction accounting, host cards and the Medium diagnosis below.
4. **Repair acceptance before buying more inference.** Written requirements
   govern grader corrections; preserve original scores with versioned diagnoses.
   A gate is a proxy, and even an independent hidden grader can contain a defect.
5. **The next product target is one accepted phase.** Reuse the flow's verified
   checkpoints where suitable; advance only after trusted acceptance and prior
   regression checks pass. An exit message or exhausted send-back cap is insufficient.
6. **Start locally with pinned Q4 and a matching host card.** A rental or another
   overnight count is not the next step. Local/pod results remain separate;
   Andre's local-Q4 parity screen does not establish universal host equivalence.
7. **Reconcile selectively, then test one change at a time.** Andre's existing
   live-server guard is the first interaction candidate; brief reasoning follows
   if traces justify it. Fresh context is a later hypothesis, not a promised saving.
8. **Keep bounded commands as the explicit stall backstop:** the [stall review](2026-11-09-phase-worker-review/stalls.md)
   records 0/122, the configured-default clamp bypass and the limits of this conclusion.

### Economics and remedy choices

**Use all-attempt cost per strict pass, then per accepted phase, for economics.**
Retain failures, retries and budget endings in the numerator; itemise censored
spend separately and include it in total economic cost without pooling its
quality/medians. Zero successes gives no finite empirical ratio.
Report success rate, fixed attempt/roadmap ceilings, p90/max, budget endings,
latency and intervention beside the ratio; include budget overshoot in actual
charges. Medians describe typical attempts.

Base's observed 43,959 charged tokens/strict pass has an approximate bootstrap
range of 32,000–62,000; Vanilla's denominator of two is unstable. Denying the
leaked r27 success while retaining every cost gives Base 45,791. These are token
proxies, not dollars: include checking, setup, human repair and fallback in a
later comparison against implementing the same phase directly with a stronger model.
Near-miss cost (15,137 versus 35,451) does not price human repair or defect severity.

**Future rules need an absolute reliability floor and fixed spending ceilings.**
Choose them before a deciding run. Neither 50,000 tokens/strict pass nor a 10%
tail rule is adopted here; both were suggested after inspecting this count.
Prefer an absolute ceiling to a moving multiple of unsuccessful Vanilla's
median. Six of Base's ten budget endings still passed strictly; always grade
the stopped snapshot. Preset promotion requires a later preregistered decision.

The [stall census and mechanism review](2026-11-09-phase-worker-review/stalls.md)
reproduce the bounded result and distinguish prevented hangs from launch/waiting
cost. Retain the bound; exercise cleanup on Linux. Do not adopt full-test display
or a lower send-back cap; the [ledger](2026-11-09-phase-worker-review/evidence.md#remedy-qualifications)
preserves their inconclusive quality and cost evidence. Turn-cap is not a hard generation stop.

## Ladder run

**No new run for this replan:** committed records, code and saved-build replay
support these corrections; the roadmap changes sequencing, not measured settings.
F.7 first qualifies the contract on positive and negative builds without inference.
F.8 makes the phase boundary verifiable; reuse existing machinery rather than
rebuilding the flow. R.1a then requests Easy Phase 2 from a strict-passing Phase-1
checkpoint, under the checked-in Easy ceiling (128 requests / 64,000 charged output).
One watched success establishes presence only. Stop to diagnose a failed attempt;
comparisons/absence need at least three per arm and a frozen, explicit configuration.

R.1b screens one cost/interaction candidate against corrected Base on the same
phase: server guard first when the trace exposes that spiral, then brief reasoning
only as a separate screen. R.2 diagnoses Medium Phase 4 from a known-good Phase 3
if needed, then exercises phases from its own accepted checkpoints. A seeded
success is not end-to-end success. Set sample sizes from the question; no automatic
large count. R.3 and A.1 reopen after a useful Medium phase workflow exists.

## Persuasion → enforcement

`tool_call` supplies bounded bash and candidate server refusals; clamp the
configured default too. `agent_before_settle` executes acceptance, but currently
conflates green, caught infrastructure error and exhausted cap. Ordinary pytest
failures/timeouts already return red. Record distinct verdicts and block advancement
on unverified exits; bounded infrastructure recovery must not become model repair.
Trusted execution, expected test inventory and supplied-test integrity matter
beside frozen source bytes. Close the handover route before stronger
isolation claims. Feedback should retain assertions and explain timeout termination.
The proxy bounds generation even before settle; the harness grades the stopped
snapshot and checkpoints only verified green. `before_provider_request` can add
brief-reasoning text, but that is persuasion and must earn its own measured effect.

## What would falsify this / Risks

A qualified replay contradicting a diagnosis requires a dated correction. If
the local next-phase trial cannot produce accepted work within its ceiling,
diagnose that phase before expanding the batch. Small screens cannot establish
reliability, a screen's missing intervention cannot reject a dormant remedy, and
the aggregate compaction/cleanup counterfactuals cannot predict a new median.
The original acceptance verdicts stand; no implementation, preset or rental is
authorised by a source document's recommendation. This replan changes no runtime.
