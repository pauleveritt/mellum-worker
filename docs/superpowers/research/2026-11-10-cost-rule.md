# The cost rule for phase work: a fixed ceiling per accepted phase and a reliability floor

## For Andre

**Date:** 2026-11-10. **Decided by:** Paul, in the open, before any run that it judges.
**What this is:** the bar that any later deciding run on phase work must meet. It replaces "at most 3×
Vanilla's median output tokens over all sessions" from the [Easy count rule](2026-11-08-easy-count-rule.md).
**What is measured:** the figures quoted below, each from its linked record. **What is conjecture:**
that a ceiling anchored to the session budget is the right price. That is a judgment, stated as one.

**The rule.** An arm meets the bar on a phase when, in a preregistered run:

1. **Cost:** all-attempt **charged output** per accepted phase is **at most 64,000** on Easy. This is the
   sum of every attempt's charged output, including failures, retries and budget endings, divided by
   the number of accepted phases.
2. **Reliability:** at least **2 of 3** attempts are accepted, with **n ≥ 12** attempts per phase.
   *Accepted* means F.8's trusted acceptance of the stopped snapshot: a strict pass plus every mediated
   test.
3. **Reported beside, not judged:** trace output per accepted phase, the median and maximum per
   attempt, budget endings, requests, wall time, compaction share and strays. Any claim that compares
   arms also reports Vanilla's acceptance count.

**Why these three.**

- **Absolute, not a multiple.** A multiple of Vanilla's median moves with an arm that almost never
  finishes. Vanilla's median is the price of stopping one check short, or of stalling. The
  [review](2026-11-09-phase-worker-review.md#economics-and-remedy-choices) asked for an absolute
  ceiling and a reliability floor, chosen before a deciding run.
- **64,000 is one Easy session budget.** The anchor is the budget the proxy already enforces per
  attempt, not a value tuned to the numbers below. In words: on average, an accepted phase may cost no
  more than one full session's spend.
- **Charged output** is the count the budget stops on. It includes compaction summaries and the proxy's
  flat 16,384 charge for a request with no usage report. That charge added 3–8% in the
  [overnight screen](2026-11-09-easy-base-spread.md). The rule names its count because the Easy count
  did not: the same data gave 4.47× in charged output and 3.43× in trace output.
- **2 of 3 at n ≥ 12** keeps a cheap arm that rarely finishes from passing on cost alone. The
  denominator already punishes failures, but with few acceptances the per-phase figure becomes unstable.

**What it does not do.**

- **It does not re-read the Easy count.** That rule was fixed before its first session; Base missed it,
  and `preset:base` and `preset:easy` stay `[]`. Promoting a preset needs a new preregistered run
  judged by this rule.
- **It sets no ceiling for Medium or Hard.** Their budgets are per run, not per phase. Before R.2's
  deciding run, Medium gets its own per-phase ceiling, anchored the same way: one Medium per-phase
  session budget, fixed before the run.
- **It changes no budget.** The per-attempt budget (128 requests / 64,000 charged output / 1,200 s on
  Easy) still stops a session. The rule judges spend across attempts.

## Ladder run

No run was made for this decision. It applies to the next preregistered deciding run on phase work,
whose preregistration must cite this note and state its arms, n and phase. The figures above come from
the Easy count (`evals/2026-11-08-easy-final-count/`) and the overnight screen
(`evals/2026-11-09-easy-base-spread/`).

## Persuasion → enforcement

The rule is enforced by the harness, not the model. The proxy stops each attempt at its budget and
records charged output. F.8's boundary decides acceptance from a trusted copy. The ceiling and floor are
computed from those records after the run, with nothing the session writes counted.

## What would falsify this / Risks

- **The anchor may be too lax.** Base already sits at 26–44k per accepted phase, so a 64,000 ceiling
  separates arms only when one fails often or runs long. A later comparison against a stronger model
  doing the phase directly could show that one session budget is too high a price.
- **The flat charge is in the count.** If the proxy reads usage it now misses, charged output falls by
  up to about 8% with no change in the work.
- **n = 12 is small for a floor of 2 of 3:** 8 of 12 meets it with a wide interval. The floor is a gate,
  not a rate estimate.
- **Host:** Phase 1 was counted on the pod and Phases 2–3 screened on the Mac. A deciding run fixes its
  host.
