## What changed

- **Mediated test** — an external, complete, frozen phase test placed in the
  baseline; the worker cannot weaken it, and the run is scored by re-running it.
- **v7 worker prompt** — "make the one named test pass": read the test and its
  spec, create the module it imports, run only the named test, never touch the
  test or add other test files.
- **Focused command** — verify with `pytest tests/<the-test>`, not the whole
  `tests/` dir (the whole-dir command made the worker chase unrelated tests — a
  93-turn spin on rung 6 under v6).
- **Trimmed tools** — `read, ls, bash, edit, write`; `grep`/`find` shell to
  `fd`/`rg`, unavailable offline, and wasted turns.
- **Fail-fast effort ramp** — 2k → 8k → 16k, escalating only on failure. Rung 9
  needed the budget (≈230–337s); the easy rungs won cheap.

## Honest scope

- n=3, one clean run. An earlier run was polluted by a concurrent duplicate
  loop (two runs sharing an out dir) and discarded — caught by the jumbled rung
  order (fail-loud).
- This is a **method** comparison (mediated + v7 + fail-fast vs the Mode +
  project-facts arms), not a single-variable ablation. It does not isolate which
  of the four changes carries the lift.
- v7 is specialized to the "make a failing test pass" shape — Mellum's
  recommended best-measured usage, but narrower than the general v6 prompt.

## Leads from here

- **Isolate the lift**: ablate v7-prompt / focused-command / trimmed-tools /
  fail-fast one at a time to see which carries the rung-9 crack.
- **Fail-fast overhead on hard rungs**: rung 9 pays the cheap-attempt tax
  (≈272s avg vs the 2026-10-18 one-shot high-budget 194s). A bigger first jump
  could recover it.
- Fixed en route: a `ProfileMismatch` crash when `--effort-ramp` escalated
  `max_tokens` past the profile's fixed value (the check now skips under the
  ramp).
