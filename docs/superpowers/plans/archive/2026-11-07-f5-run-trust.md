# F.5 — runs we can trust on the M5 Max

## For Andre

- **Why:** R.1 measures remedies on quality and budget, so the budget must be one the host cannot
  bend and the host must be shown sound. LC.39 built both for pods on `lc40-thin-worker`; this
  ports the Mac's share, test-first, and nothing about pods.
- **Budget:** a loopback proxy per session refuses past a tier's request and output-token limits
  (Easy 64 / 32,000; Medium, Hard 120 / 64,000). The session ends `budget` and counts.
  `wall_safety` (1,200 s) is a hang-guard; a run that hits it is censored.
- **Host card:** a counted session needs a passing card for the live :8001 server.
- **Decided before this plan**, with the numerics measured and where we differ from `33e0b92`:
  [note](../../research/2026-11-07-f5-run-trust.md). b12110 passes numerics (0.57%), so F.6 stays
  after R.1.
- **What to look at:** the host card and the Vanilla smoke in `## Result`.

## Scope

In: the proxy and its wiring; the Mac pin card, `conformance.py` and the host gate; Pi's version
in `run.json`; a session `PATH` without the harness venv (`7adeaa5`); the port-8000 guard; no
runs inside a project. Out: remedies and the settle fix (R.1); pods, the session user and the
isolation probe (F.6); Medium and Hard baselines; model, sampling or oracle changes; reconciling
the server log against the proxy (backlog). No spec: the worker does not change, the harness does.
