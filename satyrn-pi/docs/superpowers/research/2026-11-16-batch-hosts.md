# Rented batches: policy, cost and comparability

## What is measured / what is conjecture

**What is measured:** the source reply [refuses rented counted runs](https://github.com/andrevanzuydam/mellum-worker/blob/0e4a9b6859cbe447adbca537c5738f24a862d214/docs/superpowers/research/2026-11-13-reply-to-handover.md#L85),
stating that its M3 Max Q4 results matched a rented A6000 on Q4. This note
retrieves that position; it does not independently reproduce the comparison.
**What is conjecture:** rented-batch cost and local/rented comparability for
the rewritten Satyrn Pi stack. No rented configuration is qualified here.

## Explicit policy departure

The brief retains local screens and rented batches on RunPod or Vast as a
Satyrn Pi policy decision. This differs from the source reply as well as the
new repository's empty-presets decision. Neither is presented as source assent.

Use the model quant and b12066 server version named in
[reference rig](2026-11-16-reference-rig.md). Native local binaries and rented
CUDA images are different artifacts; "same image" is not a portable parity
claim. Each run records the artifact checksum/digest, full serve flags,
request settings and host hardware. Do not reuse the source's b11985 image
under a b12066 label.

## Owner and deadline

Before a rented batch is commissioned, its cycle's Andre/Paul implementer
records a priced candidate host, qualification and expected cost; Nicola
approves spend through the team's normal process. No amount is assumed here.
Provision the server externally and supply `--base-url` to eval. Eval never
installs, starts, stops or rents a server in these twelve phases.

Before a deciding batch, publish a preregistration fixing host, arms, n,
grading, cost reading and decision rule. If cost changes the affordable n,
change the design before the deciding run; do not stop after a favourable
result or combine unplanned host substitutions into one rate.

Host cards establish provenance, not equivalence. A comparison or pooled
claim spanning local and rented results needs its own preregistered
comparability design and evidence; otherwise report the hosts separately.
The builder chooses provider and hardware from measured capacity/cost, without
changing the subject model, quant or reference version silently.

## What would falsify this

Unavailable b12066 artifacts or unaffordable capacity would block the proposed
batch configuration and require a recorded decision before running it.
Systematic host-dependent results under the declared comparison would falsify
any proposed interchangeability claim.

## Risks

Prices, availability, driver support and offload behaviour vary. A shared
server version and quant do not remove hardware effects. No new comparative
claim or cost estimate is earned by this planning note.
